## 1. 목표와 판정 기준

**호스트가 모든 게임 규칙과 게임플레이 물리를 계산·확정하고, 게스트는 입력을 전송하고 호스트의 결과를 표현한다.** 호스트 프로세스는 게스트가 조종하는 플레이어까지 시뮬레이션한다. 게스트 프로세스에서는 자기 플레이어도 표시용 복제본이다. 로컬 프로세스의 권한과 개별 플레이어의 소유자를 혼동하지 않는다.

조사는 두 질문에 각각 답해야 한다.

1. 게스트에서 실행되면 안 되는 게임 로직·물리가 실행되는가?
2. 호스트에서 결정한 결과와 연출이 게스트에 충분하고 정확하게 전달되는가?

첫 질문만 해결하면서 효과음이나 이펙트를 없애면 요구사항을 만족하지 못한다.

| 동작 | 호스트 | 게스트 판정 |
| --- | --- | --- |
| 키·버튼 입력 수집 | 자신의 입력 수집 | 입력 의도를 전송할 수 있음. 성공·비용·타격 등 결과를 확정할 수 없음 |
| 플레이어·물고기·아이템 물리, 힘, 조인트, 접촉 판정 | 모든 대상 시뮬레이션 | 게임플레이 물리 시뮬레이션과 그 결과에 의존한 판정은 허용하지 않음 |
| AI/FSM, 타깃 선정, 저항도, 허기, 마비, 사망·부활 | 호스트가 결정 | 화면을 만들기 위해 같은 게임 로직을 다시 실행하는 것도 위반 |
| 획득·소비·건설·스폰·디스폰·시간 전환·승패 | 호스트가 확정 | 수신 결과의 복제만 가능. 복제값으로 승리 조건을 다시 평가하는 것도 조사 대상 |
| 수신 위치·회전의 보간, 카메라, UI, 애니메이션 | 표시 | 허용. 게임 상태나 충돌 결과로 되먹임되지 않아야 함 |
| 호스트가 확정한 사건의 VFX/SFX | 로컬에서도 재생 | 수신 사건·표시 상태로 재생. 게스트의 접촉·속도·AI 판정으로 사건을 새로 만들지 않음 |

| 복제본 생성·반환·비활성화 | 원본 생명주기 관리 | 호스트 결과에 따른 표시 객체 관리는 허용. 게스트가 생성 시점·종류·보상 등을 결정하면 위반 |

게스트의 모든 필드 변경, `Update`, `Time.deltaTime`, `Random`, `Instantiate`를 일괄 금지하지 않는다. 수신 값 저장, 보간 캐시, UI 시간, 장식 효과와 게임 상태를 구분한다. 단, 게임 로직을 실행한 뒤 다음 스냅샷으로 덮어쓰는 방식은 허용하지 않는다.

## 2. 범위와 예외

- 대상은 실제 게임 실행에 연결되는 프로젝트 코드, 씬, 프리팹과 변형, 자식 컴포넌트, 직렬화된 이벤트, 애니메이션 이벤트, 런타임 생성·풀링 경로다.
- `ProjectSettings/EditorBuildSettings.asset`의 현재 시작점은 `Assets/00. Scenes/MainMenu.unity`, `Assets/00. Scenes/InGame.unity`다. 실행 시 최신 설정과 동적 로드를 다시 확인한다.
- `Assets/01. Scripts` 밖이라도 게임에서 사용되는 프로젝트 코드와 동작은 포함한다. 외부 패키지 전체를 감사하지는 않되, 실제 연결된 컴포넌트의 동작은 조사한다.
- `Tester`, `Debug`, `Old`, `Sample`이라는 이름만으로 제외하지 않는다. 실제 참조·실행 여부를 확인하고 분리 기록한다.
- 튜토리얼 전용 동작은 제외한다. 시작점은 `Assets/01. Scripts/1403. Tutorials`와 튜토리얼 전용 오브젝트·이벤트다. 튜토리얼을 거쳐 일반 게임에 진입하는 권한 초기화와 공유 코드는 포함한다.
- 문어 예외는 **Octopus 투사체 발사 전용 경로**에 한정한다. `FishOctopusState.ShootBullet`, 이를 시작하는 문어 전용 트리거, `Bullet`의 전용 투사체 처리에서 범위를 확인한다. 문어가 사용한다는 이유로 공유 FSM·이동·풀·플레이어 코드를 통째로 제외하지 않는다. 같은 파일의 도주 이동 등 발사와 별개인 동작도 자동 제외하지 않는다.
- 애매한 예외 경계는 메서드와 호출 경로를 기록하고 `예외 경계 미확정`으로 남긴다. 임의로 범위를 넓혀 정상 처리하지 않는다.
- 접속 전, 역할 확정 전, 첫 스냅샷 전, 연결 종료 후에 일반 게임 로직이 어떻게 동작하는지 포함한다. `Me == null`이 자동으로 호스트 권한을 뜻하는지 검증한다. 오프라인·에디터 전용 실행과 실제 네트워크 진입 구간을 구분한다.
- 호스트 이전이나 재접속을 지원한다고 가정하지 않는다. 구현되어 있으면 조사하고, 없으면 지원 범위를 기록한다. 신규 기능 개발로 확대하지 않는다.

```text

행위별로 다음을 추적해:
실제 씬/프리팹/생성 경로 → 초기화와 권한 확정 → 실행 진입점 → 호출/이벤트/비동기 작업
→ 게임 상태·물리 변경 또는 호스트 결과 생성 → 메시지 필드/전달 경로 → 게스트 표현.

Awake, OnEnable, Start, Update, FixedUpdate, LateUpdate, OnDisable, OnDestroy,
충돌·트리거, UnityEvent, C# 이벤트, AnimationEvent, 코루틴, UniTask,
Invoke, 트윈과 완료 콜백, public 메서드, 풀 재사용을 확인해.
호스트 판정 전에 시작된 작업이 역할 확정 후에도 계속되는지 추적해.

게임 객체/컴포넌트 활성 상태, Rigidbody2D.simulated/bodyType, 자식 Collider/Joint,
레이어·접촉 설정, 풀 재활성화 순서, 역할 관련 캐시를 함께 확인해.
Kinematic 설정과 게임플레이 물리 완전 중단을 동일시하지 마.
컴포넌트를 끈 뒤 외부 호출·이벤트·비동기 작업까지 멈추는지도 실제 경로로 증명해.
Unity 동작 자체가 불확실하면 해당 버전의 공식 문서로 확인하거나 검증 필요로 남겨.

스냅샷 함수도 이름만 믿지 말고 내부에서 Grab/ChangeState/Build/EvaluateGameEnd 등을
호출해 게임 로직을 재실행하는지 확인해. 수신 상태를 저장하고 화면으로 변환하는 것은 허용한다.
호스트가 보낸 상태 이름으로 게임 FSM의 Enter/Tick을 실행하면 표현 전용이라고 간주하지 마.

게스트의 게임 로직이 정지했을 때 필요한 연출이 사라지지 않는지도 확인해.
일회성 사건과 지속 상태를 구분하고 수신 반복, 활성화 반복, 늦은 입장 시 중복·누락을 확인해.
실제 전송은 WebSocket을 사용하므로 UDP식 패킷 손실·재정렬을 당연한 전제로 삼지 마.
지연, 연결 재시작, 응용 계층 처리·큐·세션 경계 문제를 실제 구현에 맞게 판단해.

파일:줄과 호출 사슬이 없는 추측은 확정 위반으로 보고하지 마.
주석이나 과거 설계 문서를 현재 구현의 증거로 쓰지 마.
기존 MVP 계획은 참고이며 사용자의 호스트 전권 원칙을 완화하지 않는다.
문서 9절의 후보 형식, 커버리지 행, 타 담당 전달사항을 함께 제출해.
실행 테스트는 하지 말고 검증 담당이 재현할 최소 시나리오를 작성해.
```

```text
후보에 필요한 사건만 계측해. 게임 상태 변경 함수, FSM Enter/Tick/Exit,
게임플레이 물리 변경·활성 상태, 스폰/소비/건설/승패 확정,
호스트 결과 생성·수신·표현 재생 지점을 구분해.
프로세스 역할, 플레이어/WorldItem ID, 세션, 프레임 또는 시간,
수신 횟수나 계측용 사건 번호, 변경 전후 값과 호출 위치를 연결해 기록해.
계측 번호를 제품 프로토콜의 기존 필드인 것처럼 보고하지 마.
게스트의 정상적인 수신 필드 갱신과 표시 캐시 변경을 권한 침범으로 집계하지 마.

같은 장면처럼 보인다는 것만으로 성공하지 마.
게스트가 계산한 뒤 덮어쓰는 것도 잡을 수 있도록 변경 경로와 실행 횟수를 관측해.
호스트는 원격 플레이어까지 계속 계산하고, 게스트의 게임 규칙·게임플레이 물리
실행이 발생하지 않으며, 호스트 결과의 표현은 재현되는지를 각각 판정해.

아래 시나리오 표에서 후보와 연결되는 항목을 실행하고
실행 조건/절차/기대 결과/실제 결과/로그 위치를 남겨.
컴파일 성공이나 단위 테스트만으로 씬·프리팹·물리·수신 타이밍 검증을 대체하지 마.
실행하지 않은 항목은 미검증으로 남기고, validation.md를 작성해.
임시 계측이 최종 제품 변경에 섞이지 않았는지도 확인해.
```

### 실행 시나리오와 관측 기준

| 시나리오 | 관측·조작 | 기대 결과 |
| --- | --- | --- |

| 획득·건설·채굴 | 두 게스트가 같은 대상에 동시에 시도 | 호스트에서 성공·비용·보상이 확정되고 게스트가 재소비·재획득하지 않음 |
| 허기·사망·부활 | 임계값 전후와 부활 대기 동안 양쪽 관측 | 게스트에서 타이머·랜덤 힘·부활 위치 판정 없이 상태·음향·자세가 표현됨 |
| 낮밤·도착·승패 | 트리거 통과, 다리 완료, 인원 변동이 근접한 상황 | 호스트 결과가 모든 게스트에 표현되고 게스트 조건식으로 다른 결말을 확정하지 않음 |

동일 스냅샷 재적용은 애플리케이션 수신 경계의 검증이다. 실제 WebSocket 전송에서 같은 패킷이 임의로 중복·재정렬된다는 주장이 아니다. 테스트용 수신 정지 역시 게임 동작으로 도입할 기능이 아니다.

## 9. 산출물과 완료 조건

총괄은 `docs/authority-audit`에 아래 결과를 모은다. 조사 규모에 맞게 관련 표를 한 문서에 합쳐도 된다.

- `scope.md`: 기준 커밋·작업 트리, 역할/생명주기 지도, 씬·프리팹 연결, 예외와 미확인 범위.
- `A-network.md` ~ `E-world-presentation.md`: 담당별 근거, 커버리지, 후보, 타 담당 전달사항.
- `review.md`: 후보 반증, 중복 병합, 정상 판정 재검토 결과.
- `findings.md`: 최종 후보·확정 위반과 우선순위. 정적 확정과 실행 재현을 구분.
- `coverage.md`: 기능·컴포넌트별 권한 검사표와 게임 사건별 표현 전달표.
- `validation.md`: 재현 절차 및 실행 여부. 검증 담당 실행 전에는 계획만 기록.

### 이슈 기록 형식

```text
ID / 제목:
분류: 게스트 게임 로직 | 게스트 게임플레이 물리 | 표현 누락/중복 | 초기화/수신 경계
확인 수준: 정적으로 확정 | 실행으로 재현 | 추가 확인 필요
우선순위: P1(승패·자원·조작/물리의 핵심 오류), P2(그 밖의 규칙 위반·필수 연출 오류), P3(경미한 표시 문제)
실행 환경 / 씬·프리팹 / 객체·사용자 역할:
진입 조건과 호출 사슬:
근거 파일:줄 (권한 경계와 실제 부작용을 모두 제시):
게스트에서 실행/변경되는 것 또는 전달되지 않는 표현:
관련 호스트 확정 지점과 메시지 생산·수신·소비 경로:
사용자에게 보이는 영향과 발생 조건:
확인한 반증: 상위 권한 제한 / 비활성화 / 도달 불가 / 예외 / 표현 전용 여부
최소 재현 절차 / 기대 결과 / 실제 결과 또는 아직 필요한 관측:
수정 방향 한두 문장 (구현하지 않음):
검증 방법 / 로그·증거 위치 / 미확인 제약:
관련 담당 / 중복 원인 ID:
```

화면 차이가 없더라도 게스트가 실제 게임 FSM·물리를 실행하면 요구 위반으로 기록한다. 우선순위와 증거의 확실성은 별개다. 정상과 예외 항목은 이슈 수를 채우기 위해 결함으로 작성하지 않는다.

권한 커버리지 표의 최소 열:

`기능/컴포넌트 | 씬·프리팹/생성 경로 | 진입점 | 권한 변경 또는 물리 동작 | 호스트 근거 | 게스트 차단/복제 근거 | 표현 전달 근거 | 판정 | 증거/미확인 이유 | 담당`

표현 전달표의 최소 열:

`사건/지속 상태 | 호스트 확정 지점 | 메시지 필드/사건 | 게스트 소비 지점 | UI/VFX/SFX | 최초/반복/종료 처리 | 누락·로컬 판정 의존 | 증거`

각 커버리지 행의 판정은 `적합`, `위반`, `미확인`, `범위 제외`, `미사용 확인` 중 하나다. `적합`에는 호스트 실행과 게스트 차단·표현 경로의 근거가 필요하다.

정적 조사 완료 조건:

1. 실제 사용되는 모든 대상 기능·컴포넌트에 담당과 커버리지 행이 있다. 범위 밖·미사용에는 근거가 있다.
2. A~E 간 호출 사슬이 최종 게임 부작용 또는 순수 표현까지 연결된다.
3. 확정 위반마다 실행 도달 경로와 코드 근거가 있고 독립 검토의 반증 확인을 거쳤다.
4. 게임 사건별 표현 전달표가 있어 호스트 로직 차단에 가려진 게스트 연출 누락을 확인할 수 있다.
5. 실행이 필요한 후보에는 재현 절차와 관측할 값이 있다. 미확인을 정상으로 처리하지 않는다.

실행 검증 완료 조건은 선택된 시나리오의 실제 결과·증거·미실행 범위가 기록되는 것이다. 정적 조사 완료와 런타임 검증 완료를 별도로 보고한다. 발견된 결함을 고치지 않았으므로 조사 완료를 게임의 규칙 준수 완료로 표현하지 않는다.

수정 작업을 이후에 맡길 때는 확정 이슈와 재현 기준을 전달한다. 변경은 최소 범위로 제한하고, 광범위한 예외 처리·조용한 fallback·무작정 return으로 필수 흐름의 실패를 숨기지 않는다는 AGENTS.md 규칙을 유지한다.
